# 微光老师产品设计文档

版本：V1.0  
日期：2026-05-20  
依据原型：`prototype/stitch-optimized.html`  
适用对象：产品、设计、前端、后端、AI 提示词与测试人员

## 1. 产品定位

「微光老师」是一款面向教师个人的 AI 工作陪伴产品。它把教师一天中最高频的三类需求放在同一个工作台里：

- 今日教学与待办秩序
- 课间情绪恢复与自我支持
- 家校沟通记录与 AI 回复生成

本版本不是完整教务系统，也不是公开情绪社区。产品的第一屏必须让老师感到“今天的事清楚了，我也被照顾到了”，并在 3 到 5 分钟内完成一次有效操作。

## 2. 设计目标

### 2.1 用户目标

- 快速知道今天要上什么课、有哪些提醒、哪些家长需要跟进。
- 在课间、放学后等短时间窗口获得轻量疗愈支持。
- 在敏感家校沟通场景下获得专业、克制、可直接编辑的回复草稿。
- 将重要沟通沉淀为记录，降低遗漏和后续纠纷风险。
- 管理 Pro 权益、AI 用量、云同步和提醒偏好。

### 2.2 产品目标

- 以「今日洞察」作为高频入口，提高打开后的即时价值。
- 以「AI 夸夸」「白噪音」「树洞」承接情绪需求，提高留存。
- 以「AI 家长沟通」「沟通记录」形成付费价值。
- 保持界面低压、克制、专业，不制造额外任务负担。

### 2.3 设计原则

- 低打扰：提醒、弹窗、状态反馈都只在必要时出现。
- 可扫读：卡片标题、时间、标签、状态必须能在 3 秒内理解。
- 有边界的温暖：文案支持用户，但不说教、不煽动、不替用户做最终判断。
- 工具优先：所有页面都应提供可操作能力，而不是说明型内容。
- 响应式一致：桌面端适合备课和整理，移动端适合课间快速操作。

## 3. 信息架构

产品由 5 个一级模块组成：

| 模块 | 导航名称 | 主要任务 |
| --- | --- | --- |
| 今日 | 首页 / 今日洞察 | 查看今日课程、待办、家长跟进，进入高频操作 |
| 疗愈 | 疗愈空间 | 呼吸引导、AI 夸夸、树洞、白噪音 |
| 沟通 | 家校沟通 | 生成家长回复、维护关注家长、保存沟通记录 |
| 日程 | 本周日程 | 查看周课表、日安排、低打扰提醒，新增提醒 |
| 我的 | 个人中心 | 教师资料、Pro 试用、使用数据、偏好设置 |

## 4. 全局框架

### 4.1 桌面端布局

适用宽度：`> 980px`

- 页面采用左侧固定导航 + 右侧主内容区。
- 左侧导航宽度：280px。
- 主内容最大宽度：1160px，居中展示。
- 主内容顶部保留全局顶栏，顶栏吸顶。
- 内容区采用双栏网格：左栏略宽，右栏略窄，比例约 `1.08 : 0.92`。

### 4.2 移动端布局

适用宽度：`<= 980px`

- 隐藏左侧导航。
- 显示底部 5 Tab 导航：首页、疗愈、沟通、日程、我的。
- 主内容改为单列布局。
- 内容底部需预留底部导航与安全区高度。
- 顶栏保留头像、页面标题、搜索、通知入口。

### 4.3 小屏适配

适用宽度：`<= 560px`

- 标题字号收敛，避免折行过多。
- Hero 区最小高度降低。
- 数据卡片高度降低。
- 周日期选择器高度降低。
- 声音卡片保持 2 列，避免点击目标过小。

## 5. 全局导航

### 5.1 左侧导航

桌面端展示：

- 品牌区：图标 +「微光老师」+ 副标题「教师工作陪伴」

  - 首页，图标 `home`
  - 疗愈，图标 `sparkles`
  - 沟通，图标 `message-circle`
  - 日程，图标 `calendar-days`
  - 我的，图标 `user-round`
- 今日微光卡片：展示一句情绪支持文案。

交互要求：

- 点击导航项切换对应页面。
- 当前页面导航项高亮。
- Hover 时可轻微上移并改变背景，但不得造成布局跳动。

### 5.2 顶栏

顶栏包含：

- 用户头像：默认展示姓氏首字。
- 页面辅助信息：例如「周三 第 12 周 · 今日洞察」。
- 页面标题：随当前模块变化。
- 搜索按钮：当前原型仅展示入口，后续可接入全局搜索。
- 通知按钮：带红点，点击打开「添加提醒」弹窗。

页面标题映射：

| 页面 | 标题 | 辅助信息 |
| --- | --- | --- |
| 首页 | 早上好，林老师 | 周三 第 12 周 · 今日洞察 |
| 疗愈 | 疗愈空间 | 课间 5 分钟 · 白噪音与树洞 |
| 沟通 | 家校沟通 | AI 回复 · 家长档案 · 沟通记录 |
| 日程 | 本周日程 | 周课表 · 低打扰提醒 |
| 我的 | 我的 | 教师工作陪伴 · Pro 试用 |

### 5.3 移动底部导航

移动端固定底部展示 5 个 Tab。点击后：

- 切换页面内容。
- 同步更新顶栏标题和辅助信息。
- 页面滚动回顶部。
- 当前 Tab 高亮。

## 6. 首页：今日洞察

### 6.1 页面目标

让老师打开产品后快速掌握今日重点，并进入最常用操作。

### 6.2 页面结构

首页桌面端为双栏：

- 左栏：今日洞察 Hero、数据概览、快捷操作。
- 右栏：近期日程、需要关注的家长。

移动端按上述顺序纵向排列。

### 6.3 今日洞察 Hero

内容：

- 标签：「今日洞察」
- 主标题：提示今日课程数量，例如「深呼吸，今天有 3 节课等待您的指引。」
- 支持文案：强调老师在混乱消息和课程之间带来的稳定力量。
- 主操作：AI 夸夸
- 次操作：5 分钟疗愈

交互：

- 点击「AI 夸夸」跳转到疗愈页，并聚焦 AI 夸夸输入框。
- 点击「5 分钟疗愈」跳转到疗愈页。

验收标准：

- Hero 是首页第一视觉重心。
- 主操作在桌面和移动端都应位于首屏可见范围。
- 文案不应制造额外责任感。

### 6.4 数据概览

展示 3 个数据卡片：

- 今日课程：默认 3。
- 待办提醒：默认 5，可因新增提醒递增。
- 家长跟进：默认 2。

字段要求：

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| label | string | 指标名称 |
| value | number | 当前数量 |
| targetModule | enum | 可选跳转模块 |

交互建议：

- 点击「今日课程」可跳转日程页。
- 点击「待办提醒」可跳转日程页并定位提醒区。
- 点击「家长跟进」可跳转沟通页。

### 6.5 快捷操作

快捷操作为 4 个固定入口：

| 操作 | 图标 | 行为 |
| --- | --- | --- |
| AI 智能表扬 | `sparkles` | 跳转疗愈页，聚焦 AI 夸夸 |
| 记录点滴 | `message-circle` | 跳转沟通页 |
| 添加提醒 | `alarm-clock-plus` | 打开添加提醒弹窗 |
| 5 分钟疗愈 | `headphones` | 跳转疗愈页 |

设计要求：

- 第一项使用暖金强调。
- 每个快捷入口必须具备清晰点击反馈。
- 文案在移动端不应溢出卡片。

### 6.6 近期日程

展示下一项日程：

- 标题：近期日程
- 辅助说明：下一节课开始倒计时
- 状态标签：即将开始
- 课程名称
- 地点
- 时间
- 操作：查看课件

后续实现要求：

- 若无下一项，展示空状态「今天没有更多安排，可以留给自己一点空白。」
- 若课程距离开始时间小于 15 分钟，状态为「即将开始」。
- 若课程正在进行，状态为「进行中」。

### 6.7 需要关注的家长

展示最多 2 条重点关注对象：

| 字段 | 说明 |
| --- | --- |
| 家长称呼 | 例如「李明宇妈妈」 |
| 关联事项 | 例如「关于近期情绪波动的沟通」 |
| 风险/状态标签 | 高优、需跟进 |

交互：

- 点击「查看全部」跳转到沟通页。
- 点击单条家长卡片后续可进入家长档案详情。

## 7. 疗愈空间

### 7.1 页面目标

为教师提供课间 5 分钟内可完成的情绪恢复入口。

### 7.2 页面结构

- 呼吸律动卡片
- AI 夸夸卡片
- 私密树洞卡片
- 专注白噪音卡片组

### 7.3 呼吸律动

内容：

- 标题：呼吸律动
- 说明：跟随微光的节奏，深呼吸，卸下疲惫。
- 中心视觉：三层紫色圆环 + 风图标。
- 按钮：开始一分钟冥想 / 呼吸中。

交互：

- 默认静止。
- 点击按钮后，呼吸圆环进入循环动画，按钮文案改为「呼吸中」，图标改为暂停。
- 再次点击停止动画，按钮恢复「开始一分钟冥想」。

动画要求：

- 单周期约 7.2 秒。
- 圆环缩放与透明度变化应柔和，不可闪烁。
- 不播放强提示音。

### 7.4 AI 夸夸

功能目标：

根据老师输入的事件和选择的人格，生成一句具体、温柔、可收藏的回应。

输入：

| 字段 | 类型 | 必填 | 说明 |
| --- | --- | --- | --- |
| persona | enum | 是 | `senior` 温柔前辈、`director` 知心主任、`friend` 清醒同事 |
| content | textarea | 否 | 用户描述今天发生的事 |

默认人格：

- 温柔前辈。

生成规则：

- 若输入为空，使用默认场景「今天开了很久的会，还要继续处理班里的事情。」
- 回复结构为：先理解处境，再承认消耗，再给一个轻量动作建议。
- 不使用「你应该」「你必须」「再坚持一下」等增加负担的表达。

输出：

- 输出区域默认可见，展示一条示例回复。
- 点击生成后替换输出内容。
- 成功后显示 Toast：「已生成一条温柔回应」。

后续能力：

- 收藏回复。
- 生成分享卡片。
- 记录情绪标签。
- 根据近期输入推荐疗愈内容。

### 7.5 私密树洞

功能目标：

承接不方便公开表达的情绪，默认只对本人可见。

输入：

- 文本内容，支持多行。

交互：

- 内容为空时点击「放进树洞」，显示 Toast：「先写一点心情」。
- 内容非空时：
  - 清空输入框。
  - 展示 AI 温柔回应。
  - 显示 Toast：「已放进树洞」。

隐私要求：

- 默认仅自己可见。
- 后续如增加同学段可见，必须让用户主动选择。
- 树洞内容不应被自动公开或用于外显推荐。

### 7.6 专注白噪音

提供 4 个声音场景：

| 场景 | 图标 | 使用场景 |
| --- | --- | --- |
| 雨夜 | `cloud-rain` | 午休与放空 |
| Lo-fi | `radio` | 批改作业 |
| 安静教室 | `school` | 轻专注 |
| 晚间钢琴 | `music-2` | 放学后 |

交互：

- 点击任一声音卡片，进入播放状态。
- 同一时间只允许一个声音播放。
- 再次点击当前播放卡片则停止。
- 播放中展示波形动画。
- 浏览器限制播放时，保留视觉播放状态并提示环境限制。

技术要求：

- 前端可先使用 Web Audio API 模拟。
- 正式产品应替换为真实音频资源，并支持音量、暂停、后台播放策略。

## 8. 家校沟通

### 8.1 页面目标

帮助老师在敏感家校沟通中快速生成专业、温和、可编辑的表达，并沉淀重点记录。

### 8.2 页面结构

- 左栏：AI 沟通助手。
- 右栏：重点关注家长、沟通记录。
- 移动端纵向排列。

### 8.3 AI 沟通助手

输入字段：

| 字段 | 类型 | 默认值 | 说明 |
| --- | --- | --- | --- |
| 沟通要点 | textarea | 示例问题 | 描述学生情况、家长问题、期望目标 |
| 家长风格 | select | 容易焦虑 | 可选：容易焦虑、比较敏感、沟通积极、关注成绩 |
| 语气 | select | 温和 | 可选：温和、正式、简短、强硬但礼貌 |

操作：

- 点击「生成草稿」生成 4 个版本。
- 用户选择的语气版本排在第一位。
- 生成成功后 Toast：「已生成 4 个沟通版本」。

输出版本：

- 温和版
- 正式版
- 简短版
- 强硬但礼貌版

内容安全要求：

- 不指责家长。
- 不给学生贴负面标签。
- 不使用绝对化表达，例如「总是」「完全不」「肯定是」。
- 强硬版也必须保持礼貌、事实清楚、建议具体。
- 输出应默认可编辑，发送前必须由老师确认。

建议增加的后续操作：

- 复制文本。
- 保存为模板。
- 保存为沟通记录。
- 关联学生与家长档案。
- 标记后续跟进时间。

### 8.4 重点关注

展示需要近期处理的家长对象。

字段：

| 字段 | 说明 |
| --- | --- |
| 家长称呼 | 例如「林晓晓妈妈」 |
| 关注原因 | 例如「近期情绪波动大」 |
| 风险标签 | 例如「敏感对话」「需跟进」 |
| 最近沟通时间 | 例如「昨天 14:30 语音通话」 |

操作：

- 点击「新增」后续应打开家长档案创建弹窗或页面。
- 点击单条记录后续应进入档案详情。

### 8.5 沟通记录

沟通记录以时间线展示。

字段：

| 字段 | 说明 |
| --- | --- |
| 沟通对象 | 家长称呼 |
| 时间 | 昨天、周一、刚刚等 |
| 摘要 | 沟通重点与约定 |
| 状态 | 活跃记录高亮 |

交互：

- 点击「保存当前」将 AI 沟通助手中的内容保存到记录列表顶部。
- 新增记录默认标记为 active。
- 成功后 Toast：「已保存到沟通记录」。

数据要求：

- 正式实现时，沟通记录应至少包含学生、家长、沟通方式、沟通时间、沟通原因、沟通摘要、沟通结果、风险等级、下次跟进时间。

## 9. 本周日程

### 9.1 页面目标

展示一周内课程与提醒，帮助老师快速切换日期并管理低打扰提醒。

### 9.2 页面结构

- 周日期选择器。
- 今日安排时间线。
- 低打扰提醒列表。

### 9.3 周日期选择器

展示 7 个日期按钮：

- 周一 12
- 周二 13
- 周三 14，默认选中
- 周四 15
- 周五 16
- 周六 17
- 周日 18

交互：

- 点击日期后高亮当前日期。
- 更新「今日安排」列表。
- 更新日期标签，例如「周三」。

正式产品要求：

- 日期应由真实周历生成。
- 支持跨周切换。
- 今天应有独立视觉标识。
- 无课程日展示空状态。

### 9.4 今日安排

以时间线展示当前日期课程或事务。

原型数据示例：

| 日期 | 时间 | 标题 | 地点/说明 | 状态 |
| --- | --- | --- | --- | --- |
| 周一 | 08:30 | 早读监督 | 高一(2)班 · 教学楼 B102 | 普通 |
| 周一 | 10:00 | 语文阅读训练 | 高二(3)班 · 教学楼 A303 | 下一项 |
| 周三 | 10:00 | 心理健康讲座 | 高二(5)班 · 阶梯教室 2 | 下一项 |
| 周五 | 16:20 | 班主任例会 | 周末安全提醒 | 普通 |

空状态：

- 文案：「今天没有课程安排，可以留给自己一点空白。」

状态规则：

- 下一项课程增加高亮卡片和「下一项」标签。
- 已结束课程可在后续版本降低透明度。
- 进行中课程可显示「进行中」。

### 9.5 低打扰提醒

列表字段：

| 字段 | 说明 |
| --- | --- |
| 标题 | 提醒事项 |
| 时间 | HH:mm |
| 说明 | 分类与备注 |

默认示例：

- 准备互动环节道具，09:10。
- 回访陈子默爸爸，17:20。

提醒原则：

- 只提醒重要事务。
- 避免连续多次强提醒。
- 家长回访、公开课、教研会议等应支持分类筛选。

## 10. 添加提醒弹窗

### 10.1 触发入口

- 顶栏通知按钮。
- 首页快捷操作「添加提醒」。
- 日程页「添加提醒」按钮。

### 10.2 弹窗结构

字段：

| 字段 | 类型 | 默认值 |
| --- | --- | --- |
| 事项 | input | 月考后沟通许嘉木爸爸 |
| 时间 | time | 17:20 |
| 分类 | select | 家长回访 |

分类选项：

- 家长回访
- 教研会议
- 公开课
- 个人事项

操作：

- 保存提醒。
- 点击关闭按钮关闭。
- 点击遮罩关闭。

保存成功：

- 向日程页「低打扰提醒」列表追加新卡片。
- 首页待办提醒数量 +1。
- 关闭弹窗。

## 14. AI 设计

### 14.1 AI 夸夸提示词要求

输入：

- 用户文本。
- 人格类型。
- 近期情绪，可选。

输出要求：

- 80 到 160 字。
- 具体回应用户输入。
- 先理解，再安慰，再给一个小动作。
- 不否定疲惫。
- 不输出医疗诊断。
- 不要求用户继续承担更多责任。

人格差异：

| 人格 | 语气 |
| --- | --- |
| 温柔前辈 | 稳、柔和、像有经验的同事 |
| 知心主任 | 专业、结构化、承认职业价值 |
| 清醒同事 | 直接、轻松、有边界感 |

### 14.2 AI 家长回复提示词要求

输入：

- 沟通要点。
- 家长风格。
- 目标语气。
- 学生称谓，可选。
- 发送渠道，可选。

输出：

- 固定 4 个版本：温和版、正式版、简短版、强硬但礼貌版。
- 每个版本建议 80 到 180 字。
- 输出可直接复制，但必须提醒用户发送前确认。

约束：

- 不贴标签。
- 不扩大事实。
- 不暗示学生存在未经确认的问题。
- 不使用威胁性语言。
- 给出可执行的家庭配合建议。

## 18. 验收标准

### 18.1 页面完整性

- 5 个一级模块均可通过桌面侧栏和移动底部导航访问。
- 顶栏标题和辅助信息随页面同步更新。
- 页面切换后滚动回顶部。
- 所有按钮具备可感知反馈。

### 18.2 响应式

- 桌面端显示侧栏，隐藏底部导航。
- 移动端隐藏侧栏，显示底部导航。
- 双栏内容在移动端变为单列。
- 文本不溢出卡片和按钮。

### 18.3 核心交互

- 首页 AI 夸夸入口能跳转疗愈页并聚焦输入框。
- 添加提醒弹窗可打开、关闭、保存。
- 保存提醒后提醒列表新增项，首页待办数量递增。
- AI 夸夸可根据人格生成不同语气输出。

- 日期切换可更新课程列表。
- 白噪音同一时间只允许一个场景播放。
- Switch 可切换状态。

- AI 夸夸不说教、不施压。
- 家长回复不指责、不贴标签、不夸大事实。
- 树洞默认私密。
- 高风险沟通应提示老师发送前确认。

## 19. 页面功能与按钮闭环清单

本节用于把每个页面的功能、按钮、点击结果和数据闭环说清楚。一个功能闭环至少包含 5 个环节：用户触发、系统响应、数据变化、结果反馈、下一步可去向。

### 19.1 全局闭环规则

所有按钮和可点击卡片必须符合以下规则：

- 点击后必须有明确结果，不能只改变视觉状态。
- 涉及保存、生成、支付、同步等异步行为时，必须有 loading、成功、失败状态。
- 异步操作进行中应禁用重复提交，避免重复生成、重复保存或重复扣费。
- 保存成功后，相关页面的数据必须同步更新，例如首页待办数、日程提醒列表、沟通记录列表。
- 失败时保留用户输入，不清空表单。
- 页面跳转后需要更新顶栏标题、导航选中态，并滚动到页面顶部。
- 所有弹窗都必须支持关闭按钮、遮罩关闭和键盘 Esc 关闭。

## 20. 当前原型与正式产品差距

当前 `stitch-optimized.html` 是静态高保真原型，存在以下待工程化事项：

- 数据均为前端写死，尚无真实后端。
- AI 生成是本地字符串拼接，尚未接入模型服务。
- 提醒仅在当前页面追加，刷新后丢失。
- 白噪音为 Web Audio 模拟，不是真实音频资源。
- 搜索按钮仅为占位入口。
- 个人中心的「生成教案」统计与当前信息架构不完全一致，需确认是否纳入 V1。
- 未实现登录、云同步、会员支付、权限控制。
- 未实现家长档案详情页、课程详情页、提醒编辑页。
- 多个按钮当前只有视觉入口，已经在第 19 节列出需要补齐的闭环。
